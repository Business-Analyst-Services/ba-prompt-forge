# Decision Support Paper (Options Analysis)

Derived from `BB-08-D2` in the BA Prompt Forge library
(Business BA / Strategic Business Analysis & Advisory, scored 20/20
against the CARE + G.E.T. rubric).

## When to use this

The user is doing strategic business analysis & advisory work and needs one of:
- Decision Support Papers
- Options Assessments
- Strategic Cost Analysis inputs

The audience for whatever you produce is: **The decision forum (executives); written so a member who reads only page one can decide**.

## Before you start

The user's work must respect the user's organisation's privacy, information-security and data-residency obligations. Everything the user pastes is de-identified or synthetic — if any input appears to contain real personal or sensitive data, stop and alert them before proceeding.

Collect these inputs from the user. Do not guess them:

1. `[PROJECT NAME AND ONE-LINE DESCRIPTION]`
2. `[STATE THE QUESTION]`
3. `[LIST OR 'GENERATE 3-4']`
4. `[WHAT MATTERS — cost, risk, speed, capability, workforce impact]`
5. `[FORUM, DATE]`
6. `[FINANCE TO ESTIMATE where unknown]`

Then ask up to 5 clarifying questions about anything still
missing, and **wait for the answers** before drafting.

## What to produce

- Produce a decision support paper that lets the forum decide in one sitting: clear question, evidenced options, explicit trade-offs, recommendation with conditions. Draft the paper. Include a 'challenge' paragraph: the strongest argument against your own recommendation.

Format the output exactly as follows:

> One-page structure: the decision required (one sentence); background (three sentences max); options table (option, what it means, benefit, cost magnitude [FINANCE TO ESTIMATE where unknown], risk, workforce/organisational impact); trade-off narrative; recommendation with conditions and first steps; what happens if no decision is made. Appendix: detailed analysis per option.

Keep the language professional, plain-English and appropriate for a business audience.

## Rules

- Do not invent facts or figures: mark anything you could not verify from the user's inputs as [TBC] and any value you propose yourself as [PROPOSED — VALIDATE].
- Treat the output as a first draft for the user's review, not a finished artefact.
- Do not ask the user to paste real personal or sensitive data.

## Worked example to imitate

Example options row: "Option C – Consolidate the two intake teams: Benefit: removes duplicate triage (~[TO BE QUANTIFIED] FTE-hours/wk); Cost magnitude: low-medium [FINANCE TO ESTIMATE]; Risk: medium — enterprise agreement consultation required; Org impact: 2 team structures merge, 1 leadership role affected."

## Before you hand it back

1. **Explain** - break down, step by step, the logic you used: how you interpreted
   each input and why you structured the output the way you did.
2. **Test** - list the sources you drew on (the user's inputs, earlier turns, or
   your own general knowledge; label which is which), cross-reference the key facts
   against them, flag anything that does not trace back to a source, and list every
   assumption you made so the user can verify or correct it.
