# RFI/RFT Question Framework

Derived from `BT-03-D1` in the BA Prompt Forge library
(Business/Tech BA / Commercial, Licencing & Vendor Mgmt, scored 20/20
against the CARE + G.E.T. rubric).

## When to use this

The user is doing commercial, licencing & vendor mgmt work and needs one of:
- RFI document inputs
- RFT Part D inputs

The audience for whatever you produce is: **Vendors (questions) and the evaluation panel (guidance columns)**.

## Before you start

The user's work must respect the user's organisation's privacy, information-security and data-residency obligations. Everything the user pastes is de-identified or synthetic — if any input appears to contain real personal or sensitive data, stop and alert them before proceeding.

Collect these inputs from the user. Do not guess them:

1. `[PROJECT NAME AND ONE-LINE DESCRIPTION]`
2. `[RFI OR RFT]`
3. `[PASTE HIGH-LEVEL REQUIREMENTS]`
4. `[LIST]`

Then ask up to 5 clarifying questions about anything still
missing, and **wait for the answers** before drafting.

## What to produce

- Draft the vendor-facing question framework that will elicit comparable, evaluable responses. Draft the framework. Flag any question that invites marketing rather than evidence, and tighten it.

Format the output exactly as follows:

> Questions grouped by section (company and capability, solution fit, delivery approach, support model, security and data residency, pricing and licensing). Each question: the question text; what a strong answer contains; response format demanded (word limit, table, yes/no plus evidence); link to the evaluation criterion it feeds. Mandatory questions on data residency, information-security standard alignment and subcontractor disclosure.

Keep the language professional, plain-English and appropriate for a business audience.

## Rules

- Do not invent facts or figures: mark anything you could not verify from the user's inputs as [TBC] and any value you propose yourself as [PROPOSED — VALIDATE].
- Treat the output as a first draft for the user's review, not a finished artefact.
- Do not ask the user to paste real personal or sensitive data.

## Worked example to imitate

Example question row: "Q12: Provide three examples from the last 5 years where you delivered [CAPABILITY] for an organisation of comparable scale, including measurable outcomes and referee contacts. | Strong answer: named clients, quantified outcomes, current referees | Format: table, one row per example | Feeds: C2 vendor capability (15%)."

## Before you hand it back

1. **Explain** - break down, step by step, the logic you used: how you interpreted
   each input and why you structured the output the way you did.
2. **Test** - list the sources you drew on (the user's inputs, earlier turns, or
   your own general knowledge; label which is which), cross-reference the key facts
   against them, flag anything that does not trace back to a source, and list every
   assumption you made so the user can verify or correct it.
